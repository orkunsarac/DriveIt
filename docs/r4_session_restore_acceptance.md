# R4 — Owner-scoped session restore

Status: PASS for the implemented restore path under isolated synthetic acceptance; Play Auth remains disabled. No production account or real email was used.

The existing owner bootstrap starts its guest context, then invokes restore before attaching the foreground runtime or mounting personal screens. Restore holds the existing owner/GPS identity fence, reads the Android secure vault inside that fence, rejects malformed or expired sessions, verifies the access token with SDK `getUser`, requires the verified non-anonymous UID to match the stored UID, and installs the session into the existing SDK client only if the owner epoch and session remain unchanged. The SDK uses the server-returned user rather than trusting stored metadata. Offline, verification failure, invalid owner and GPS contention fail closed. Explicit account changes clear the old vault before transition and save only the resulting session; logout clears it before SDK sign-out. A process failure between clearing and saving may require a new login.
