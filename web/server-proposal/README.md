# Web deletion server proposal — not deployed

`cors.mjs` is an isolated proposal, not imported by the production function. After a real domain is approved, review its exact HTTPS origin and wrap the existing delete-account handler, then test OPTIONS, errors, native clients, and existing worker calls before a separately approved deployment. Do not use wildcard origins or cookies. CORS is not authorization: retain JWT validation, expectedOwner comparison, password reauthentication, receipt hash verification, and worker token checks unchanged. Preserve verify_jwt=false for receipt-only resume. Verify the Supabase gateway itself also allows preflight and forwards required headers.

Browser recovery remains blocked: a receipt is a bearer capability and browser local/session storage is readable by same-origin JavaScript and can be evicted. A durable user-controlled recovery export with explicit acknowledgement before request, safe import, owner separation, XSS/CSP hardening, lost-file handling and request/retry race tests needs implementation and review before activation. No receipt or password belongs in URLs, logs, analytics, or source control. Pending, busy, blocked_planet, network errors and ambiguous responses are never completion. Only a server `completed` response can be shown as complete. Do not turn on web deletion until that work and legal approval are complete.
